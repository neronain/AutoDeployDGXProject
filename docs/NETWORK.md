# พอร์ตและโปรโตคอลที่ LMDS ใช้

เขียนไว้เพราะคำถามนี้มาถึงตอนที่สายเน็ตเดินไปแล้ว — ไฟร์วอลล์ตั้งเสร็จ เครื่องอยู่หลัง NAT
และคนที่ต้องเปิดพอร์ตให้ ไม่ใช่คนเดียวกับคนที่ติดตั้ง

> ทุกพอร์ตในนี้ **ตั้งค่าได้** ตัวเลขที่เขียนคือค่าเริ่มต้น

LMDS มีสองบทบาทที่ใช้พอร์ตต่างกัน — ดู [FLEET-MULTI-NODE.md §1.5](FLEET-MULTI-NODE.md)
ว่าเครื่องไหนเป็นบทบาทอะไร

---

## เครื่องที่เป็น hub (คนที่เปิดคอนโซล)

### ขาเข้า

| พอร์ต | โปรโตคอล | ใครเรียก | จำเป็นไหม |
|---|---|---|---|
| **8600/tcp** | HTTP | ผู้ดูแลที่เปิดคอนโซล | เฉพาะเมื่อใช้หน้าเว็บ |

`lmds web` ผูกกับ `127.0.0.1` เป็นค่าเริ่มต้น — เข้าจากเครื่องอื่นไม่ได้จนกว่าจะสั่ง
`--host 0.0.0.0` เอง · **ไม่มี TLS ในตัว** ถ้าต้องเปิดออกนอกวงให้วาง reverse proxy
หรือใช้ SSH tunnel แทน:

```bash
ssh -L 8600:127.0.0.1:8600 user@hub    # แล้วเปิด http://localhost:8600
```

คอนโซลใช้ token — ดูได้จาก `lmds web` ตอนสั่งรัน

### ขาออก

| ปลายทาง | พอร์ต | เมื่อไร |
|---|---|---|
| node ทุกเครื่องในทะเบียน | **22/tcp** (ตั้งต่อเครื่องได้) | ทุกคำสั่งข้ามเครื่อง |
| huggingface.co | **443/tcp** | ตอนวิเคราะห์โมเดลและโหลด weight |
| github.com | **443/tcp** | ปุ่มอัปเดต **ของ hub** เท่านั้น — node รับโค้ดจาก hub ผ่าน SSH ไม่ต้องถึง GitHub |

**hub คุย node ผ่าน SSH เท่านั้น** ไม่มี daemon ให้เปิดพอร์ตเพิ่ม — node ที่ปิดพอร์ต
ทุกตัวยกเว้น 22 ก็ยังถูกสั่งงานได้ครบ

## เครื่องที่รันโมเดล (node)

### ขาเข้า

| พอร์ต | โปรโตคอล | ใครเรียก | จำเป็นไหม |
|---|---|---|---|
| **22/tcp** | SSH | hub | **ใช่** |
| **8000/tcp** ขึ้นไป | HTTP | เกตเวย์ / client ที่เรียกโมเดลโดยตรง | ตามที่ตั้ง |

พอร์ตของโมเดลเลือกเองตอน deploy หรือเปลี่ยนทีหลังด้วย:

```bash
lmds set <slug> --port 8010
lmds restart <slug> --port 8010     # ครั้งเดียว ไม่บันทึก
```

หนึ่งเครื่องรันหลายโมเดลได้ แต่ **ต้องคนละพอร์ต** — controller ตรวจให้และปฏิเสธถ้าชนกัน
ในฟลีตจริงมักไล่เป็น 8000, 8001, 8010, 8020

### ขาออก

| ปลายทาง | พอร์ต | เมื่อไร |
|---|---|---|
| huggingface.co | **443/tcp** | ตอนโหลด weight (ทาง llama.cpp ใช้ curl/aria2c · ทาง vLLM ใช้ huggingface_hub) |
| registry ของ container | **443/tcp** | เฉพาะ engine ที่รันในคอนเทนเนอร์ (vLLM/SGLang) ตอนดึง image |

โหลด weight เสร็จแล้วรันแบบไม่มีเน็ตได้ · `lmds doctor` ตรวจไฟล์จากดิสก์ ไม่ต้องต่อออก

## แบบ stacked (โมเดลเดียว หลายเครื่อง)

ใช้เมื่อโมเดลใหญ่เกินหนึ่งเครื่อง · **เครื่องในกลุ่มต้องคุยกันได้ทุกพอร์ต**

| พอร์ต | ใช้ทำอะไร |
|---|---|
| **8000/tcp** (หรือที่ตั้งไว้) | head เท่านั้น — เป็นที่ที่ client เรียก |
| **18000/tcp** | worker รับงานจาก head (ภายในกลุ่ม) |
| **พอร์ตสูงแบบสุ่ม** | NCCL คุยกันเองระหว่างการ์ด |

NCCL เลือกพอร์ตเองตอนรัน จึงเปิดเป็นรายพอร์ตไม่ได้ — **วางเครื่องในกลุ่มไว้วงเดียวกัน
ที่ไม่มีไฟร์วอลล์กั้น** เป็นทางเดียวที่ใช้ได้จริง · ถ้ามี ConnectX/200G ให้ระบุอินเทอร์เฟซ
ด้วย `lmds node set <ชื่อ> --cluster-iface` ไม่งั้น NCCL อาจไปเลือกสายช้า

### สาย ConnectX ของ DGX Spark (วงคลัสเตอร์ — แยกจากสายบริหาร)

| พอร์ต QSFP | interface (เหมือนกันทุกเครื่อง) | RoCE | LMDS ตั้ง IP ที่ |
|---|---|---|---|
| 1 (ข้าง RJ45) | `enp1s0f0np0` · `enp1s0f1np1` | `rocep1s0f0` · `rocep1s0f1` | `enp1s0f1np1` |
| 2 | `enP2p1s0f0np0` · `enP2p1s0f1np1` | `roceP2p1s0f0` · `roceP2p1s0f1` | `enP2p1s0f1np1` |

หนึ่งช่อง = สอง interface (PCIe Gen5 x4 สองเส้น) ใช้ตัวเดียวต่อช่อง · `lmds cluster apply` แจกวงละลิงก์
เริ่มที่ `10.100.152.0/24` (ลิงก์ถัดไป `.153` `.154`) ปลาย `.1`/`.2` — ผ่าน switch ใช้วงเดียว เครื่องที่ i = `.i` ·
ตัวที่ยังไม่ได้ตั้งจะถือ `169.254.x.x` (link-local) ซึ่งข้ามเครื่องไม่ถึง · วงนี้ **ไม่มี gateway** และไม่ควรมี
อะไรวิ่งออกนอกจาก NCCL/ssh ระหว่างสมาชิก · ไฟล์: `/etc/netplan/99-lmds-cluster.yaml` (ถอนแล้วไปอยู่ที่
`/root/netplan-disabled/`) · ขั้นตอนเต็มใน [RUNBOOK-MULTI-NODE.md](RUNBOOK-MULTI-NODE.md#cluster-network-setup--ต่อสาย-connectx-แล้วให้-hub-ตั้ง-ip-ให้-060)

## ถ้าใช้ port forward

**เครื่องที่รันโมเดลอยู่หลัง NAT แล้ว forward ออกมา** เป็นรูปแบบที่เจอบ่อย

ปัญหาเดียวที่เจอคือ **ที่อยู่ที่ระบบบอกให้ client ใช้** — controller รู้แค่ IP ในวงของมันเอง
ซึ่งไม่ใช่ที่อยู่ที่คนนอกใช้ได้ · สั่งให้มันประกาศที่อยู่จริงได้:

```bash
lmds restart <slug> --advertise-ip 203.0.113.10      # ที่อยู่ที่คนนอกใช้
lmds restart <slug> --interface eth1                 # หรือระบุอินเทอร์เฟซให้เลือกเอง
```

ตรวจว่าประกาศอะไรออกไปด้วย:

```bash
lmds node run <ชื่อ> network-info <slug>
lmds node run <ชื่อ> client-config <slug>     # base URL + ชื่อโมเดลที่ client ต้องใช้
```

**ที่ไม่ต้องกังวล**

* `lmds doctor`, `wait_health` และปุ่มทดสอบทั้งหมดยิงที่ `127.0.0.1` บนเครื่องนั้นเอง
  — ทำงานได้ปกติแม้อยู่หลัง forward
* hub ไม่ต้องเข้าถึงพอร์ตของโมเดลเลย มันสั่งงานผ่าน SSH อย่างเดียว

## เครื่องนั้นอยู่ IP ไหน

ทะเบียนของ hub เก็บ **ที่อยู่ที่ใช้ SSH** ซึ่งไม่ใช่คำตอบเดียวกับ "เครื่องนั้นอยู่ IP ไหนในวง":

* ที่อยู่ SSH เป็น **ชื่อ** ได้ — `orb`, `spark1.local`, ชื่อบนเครือข่าย Tailscale
* เครื่องที่อยู่หลัง NAT (คอนเทนเนอร์ · VM ของ OrbStack) มองจาก hub เป็นคนละที่อยู่กับที่
  เครื่องข้าง ๆ มันในวงเดียวกันใช้เรียกกันเอง
* เครื่องหนึ่งมีได้หลายเส้นพร้อมกัน — สายบริหารจัดการ, สาย ConnectX ของคลัสเตอร์, Tailscale

ทุกหน้าจอจึงแสดง **IP ที่เครื่องนั้นรายงานว่าตัวเองถืออยู่** คู่กับที่อยู่ SSH เสมอ:

```bash
lmds info                    # ทุกเส้นของเครื่องนี้ พร้อม prefix และชื่อการ์ด
lmds ps                      # หัวตาราง · เครื่องที่มีเส้นเดียวไม่พูดซ้ำ
lmds node list               # คอลัมน์ "IP ของเครื่อง" — ค่าล่าสุดที่ทะเบียนจำไว้
lmds ps --all                # คอลัมน์ IP ของทุกเครื่องในทะเบียน
```

ในคอนโซล ป้าย IP อยู่บนบรรทัดชื่อของแต่ละเครื่อง (เห็นได้ทั้งตอนย่อและตอนกาง) และการ์ด
**System** แจกแจงทุกเส้น — ตัวหนา = เส้นที่ออกเน็ต · จาง = link-local (`169.254.x.x`
คือเส้นที่ลิงก์ขึ้นแล้วแต่ยังไม่ได้ตั้งค่า IP จริง)

ค่านี้มาจาก `lmds agent info` ของเครื่องนั้นเอง และถูกจำไว้ในทะเบียน — เครื่องที่ต่อไม่ได้
จึงยังบอกได้ว่า **ครั้งสุดท้ายที่เห็นมันอยู่ IP ไหน** ซึ่งเป็นตอนที่ต้องใช้พอดี

> คนละอย่างกับ `cluster_ip` — อันนั้นคือเส้นที่ **บังคับ** ให้ NCCL ใช้ตอน stacked
> ตั้งด้วย `lmds node set <ชื่อ> --cluster-ip` (ดู [FLEET-MULTI-NODE.md](FLEET-MULTI-NODE.md))

## ตรวจว่าเปิดถูกไหม

```bash
lmds node list                    # hub ต่อ SSH ถึงทุกเครื่องไหม
lmds node run <ชื่อ> ps            # เครื่องนั้นรันอะไรอยู่ พอร์ตไหน
lmds doctor <slug>                # บนเครื่องนั้น: ไฟล์ พอร์ต และเซิร์ฟเวอร์
curl -s http://<node>:8000/v1/models | head -c 200    # จากเครื่องที่จะเรียกใช้จริง
```
