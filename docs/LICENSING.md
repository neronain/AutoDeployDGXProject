# ระบบไลเซนส์ของ LMDS

> เอกสารนี้อธิบาย **สิ่งที่โปรแกรมทำจริง** · เงื่อนไขทางกฎหมายอยู่ใน [`LICENSE`](../LICENSE)
> ถ้าสองไฟล์นี้ขัดกัน ถือว่า `LICENSE` ถูก และโค้ดเป็นบั๊ก

## สรุปหนึ่งย่อหน้า

เครื่องที่ **เสิร์ฟโมเดลได้** 1 เครื่อง (บวก control plane กี่เครื่องก็ได้) ใช้ฟรีทุกวัตถุประสงค์
รวมเชิงพาณิชย์ **โดยไม่ต้องมีไฟล์ไลเซนส์เลย** · ตั้งแต่ 2 เครื่องที่บริหารร่วมกันขึ้นไปต้องมีใบ
ใบเป็นไฟล์ YAML ลงนาม Ed25519 ที่ตรวจบนเครื่องนั้นเอง — **ไม่มีการต่อออกเน็ต ไม่มี
activation server ไม่มี telemetry**

## ทำไมออกแบบแบบนี้

รีโปเป็นสาธารณะ เป็น Python และ `install.sh` ทำ `git clone` — ใครจะลบ `if` ทิ้งก็ทำได้ใน 5 นาที
**เราไม่ได้พยายามทำ DRM** เป้าหมายที่เป็นจริงคือ:

- กันการใช้เชิงพาณิชย์แบบ "ไม่รู้ว่าต้องจ่าย"
- ทำให้ซื้อง่ายกว่าแคร็ก
- มีหลักฐานตอนบังคับใช้
- พาร์ตเนอร์แยกของแท้กับของเถื่อนได้

ตลาดที่ LMDS ไปคือ DGX ในองค์กร ซึ่งเป็น **ตลาด air-gapped** ไลเซนส์จึงต้องเป็นไฟล์ออฟไลน์
ล้วน · `SECURITY.md` ของเราสัญญาว่าไม่มี telemetry และเราจะไม่ผิดคำพูดนั้นเพื่อขายของ
ข้อนี้เป็น **จุดขาย** ด้วย: คู่แข่งที่บังคับ phone-home เข้าตลาดนี้ไม่ได้

## กฎเหล็กสามข้อ

ละเมิดข้อไหนถือเป็น **บั๊ก** ไม่ใช่ทางเลือกในการออกแบบ · `tests/test_licensing.py` คุมไว้ทั้งสามข้อ

**1. ห้ามล็อกอะไรที่กันผู้ใช้เจ็บตัว**
quality gates · `doctor` · `repair` · `validate` · preflight · secret redaction · allowlist ·
approval ticket → **ฟรีตลอดกาล** คนใช้ฟรีที่ deploy พังแล้วโดนแฮ็กจะด่าชื่อเรา

**2. ห้ามหยุดของที่รันอยู่ เด็ดขาด**
หมดอายุ = อ่านอย่างเดียว (ขยายฟลีตไม่ได้) แต่ `ps` `logs` `doctor` `stop` `start` `restart`
ยังทำได้ทั้งหมด · ถ้าลูกค้ารีบูตตี 3 แล้ว autostart ไม่ทำงานเพราะไลเซนส์หมดเมื่อวาน
= เสียลูกค้ารายนั้นถาวร และสมควรแล้ว

**3. ล็อก "ขนาด" ไม่ล็อก "ความสามารถ"**
คนใช้ฟรีทำครบทั้งลูปบนเครื่องเดียว — ทุกคำสั่ง ทุก engine · สิ่งเดียวที่ต่างคือ
*จำนวนเครื่องที่บริหารร่วมกัน*

## นับเครื่องยังไง

ตาม [`LICENSE §1.1`](../LICENSE) — ไม่ใช่นับแถวในทะเบียน:

| สิ่งที่มี | นับเป็น |
|---|---|
| `llama-server` ที่รันได้ **หรือ** docker + NVIDIA GPU ≥ 1 ใบ | **1** |
| ไม่มีทั้งสองอย่าง (control plane — ใช้วางแผน generate push เปิดหน้าเว็บ) | **0 — ฟรี ไม่นับ** |
| GPU 8 ใบในเครื่องเดียว | **1** (นับเครื่อง ไม่ใช่การ์ด) |
| หลาย container บนเครื่องเดียว | **1** |
| เครื่องที่ยังไม่เคย probe | **0 — ไม่นับ** และบอกให้เห็นว่านับไม่ครบ |

ข้อสุดท้ายสำคัญ: **ผิดพลาดไปทางไม่บล็อกเสมอ** ถ้าเดาว่าเครื่องที่ยังไม่รู้จักเป็นเครื่องเสิร์ฟ
เราจะบล็อกคนที่ไม่ได้ทำอะไรผิด · แต่ต้องแสดงให้เห็น ไม่ใช่เงียบ

ดูตัวเลขที่เรานับได้: `lmds license seats`

## จุดบังคับใช้ — มีที่เดียว

```
src/lmds/licensing/enforce.py     ← รายการล็อกทั้งหมดอยู่ในไฟล์นี้ไฟล์เดียว
src/lmds/nodes/ssh.py             ← จุดที่เรียกใช้จริง (install_lmds)
```

`grep -rn "licensing.require(" src/` ครั้งเดียวเห็นครบ — มีเทสบังคับว่าห้ามมี `require()`
ที่อื่น ลูกค้าองค์กรที่ต้อง audit โค้ดก่อนซื้ออ่านไฟล์เดียวจบ

| ความสามารถ | ล็อกเมื่อไร |
|---|---|
| `fleet.grow` | ติดตั้ง LMDS ลง **เครื่องที่เสิร์ฟได้เครื่องใหม่** เกินจำนวนที่ใบครอบคลุม |
| `fleet.write` | ส่งของไปเครื่องอื่นขณะไลเซนส์ **หมดอายุ** — ของที่รันอยู่ไม่ถูกแตะ |

อัปเดตเครื่องที่นับอยู่แล้ว **ไม่เคยถูกห้าม** (กฎข้อ 2) · control plane เพิ่มได้ไม่จำกัด
ก่อนจะบล็อก เราถามเครื่องปลายทางผ่าน SSH ก่อนว่าเสิร์ฟได้จริงไหม — ถ้าตอบไม่ได้ ไม่บล็อก

## ไฟล์ไลเซนส์

`~/.config/lmds/license.yaml` (0600)

```yaml
license:
  id: LMDS-20260920-A1B2C3
  tier: team
  licensed_to: บริษัท ตัวอย่าง จำกัด
  machines: 8              # 0 = ไม่จำกัด
  issued: 2026-09-20
  expires: 2027-09-20      # ไม่มีบรรทัดนี้ = ไม่มีวันหมดอายุ
  contact: ops@example.com
signature:
  key: k1
  value: <base64 ของลายเซ็น Ed25519>
```

ลายเซ็นอยู่บน **canonical JSON** ของบล็อก `license:` (เรียงคีย์ · ไม่มีช่องว่าง · UTF-8)
ไม่ใช่บนตัวข้อความ YAML — ไฟล์จึงจัดรูปแบบใหม่ได้ เพิ่ม comment ได้ โดยลายเซ็นยังใช้ได้

### สถานะมีสี่แบบ

| สถานะ | หมายความว่า | สิทธิ์ |
|---|---|---|
| `free` | ไม่มีไฟล์ | 1 เครื่อง — **ปกติ ไม่ใช่ error** |
| `active` | ลายเซ็นถูก ยังไม่หมดอายุ | ตามใบ |
| `expired` | ลายเซ็นถูก เลยวันหมดอายุ | เท่าโหมดฟรี + อ่านอย่างเดียว |
| `invalid` | ไฟล์เสีย/ลายเซ็นไม่ผ่าน/กุญแจถูกถอน | เท่าโหมดฟรี |

`invalid` **ไม่เคยทำให้โปรแกรมหยุด** — ไฟล์พังไม่ควรทำให้เครื่องที่กำลังเสิร์ฟลูกค้าใช้ไม่ได้
และใบที่ใช้ไม่ได้ **จะไม่เขียนทับใบเดิมที่ยังดีอยู่**

## คำสั่ง

```bash
lmds license show      # สถานะ + ตัวเลขที่นับได้
lmds license seats     # นับใครบ้าง และทำไม
lmds license install <ไฟล์>
```

หน้าเว็บ: **Hub settings → License** (วางเนื้อไฟล์ลงช่องแล้วกด Install)

## กุญแจ

ฝัง public key ไว้ **สองดอก** (`k1` ใช้อยู่ · `k2` สำรองไว้หมุน) ใน
`src/lmds/licensing/keys.py` · ถ้าฝังดอกเดียวแล้ววันหนึ่งต้องเปลี่ยน จะต้องบังคับให้ลูกค้า
ทั้งฟลีตอัปเกรดพร้อมกันก่อนถึงจะต่ออายุได้ ซึ่งบนเครื่อง air-gapped คือเรื่องใหญ่

**private key ไม่อยู่ในรีโปนี้** และเครื่องมือออกใบก็ไม่อยู่ — อยู่แยกที่
`lmds-license-authority/` (ดู README ที่นั่น) เพราะรีโปนี้เป็นสาธารณะและมีแต่ฝั่งตรวจ

## การตรวจลายเซ็น

ใช้ `cryptography` ถ้าเครื่องนั้นมี · ไม่มีก็ใช้ตัวที่อยู่ใน `licensing/ed25519.py`
(RFC 8032 reference) เพื่อให้เครื่อง air-gapped ที่ลง wheel ที่ต้องคอมไพล์ไม่ได้ยังใช้ได้

ทั้งสองทางถูกเทสด้วย **test vector ของ RFC 8032 ชุดเดียวกัน** และมีเทสที่เทียบสองทาง
ตรง ๆ ว่าตอบเหมือนกันทุกอินพุต — รวมอินพุตพิลึก

> เคสจริง 2026-09-20: `verify(ศูนย์ 32 ไบต์, "x", ศูนย์ 64 ไบต์)` ให้ **True** บน
> cryptography/OpenSSL (ตรวจแบบ cofactorless ไม่ปฏิเสธจุด small-order) แต่ให้ **False**
> บนตัวที่เราเขียนเอง — เครื่องสองเครื่องในฟลีตเดียวกันจะตัดสินไฟล์เดียวกันไม่เหมือนกัน
> ขึ้นกับว่าเครื่องไหนบังเอิญมี cryptography ลงไว้ · แก้ด้วยการย้ายด่านตรวจรูปแบบ
> (ความยาว · จุด small-order · `s` ที่ reduce แล้ว) มาไว้ **ก่อน** แยกทาง

## สิ่งที่ยังไม่ได้ทำ

- **ตราประทับบน bundle** (`licensed_to` / `license_id` ใน `MODEL_PROFILE.yaml` + gate ที่ 12)
  — ไม่ใช่การล็อก แต่ทำให้ตรวจได้ว่าพาร์ตเนอร์ A เอาไปขายต่อในนาม B
- **ระดับ Maker ฟรี 2 เครื่อง** — แผน WS-7 เสนอไว้ (stacked pair ใช้ 2 พอดี) แต่ `LICENSE`
  ที่ประกาศไปแล้วเขียนว่า 1 · **ถ้าจะเปลี่ยนต้องแก้ `LICENSE` ก่อน แล้วค่อยแก้
  `FREE_SERVING_MACHINES`** ไม่ใช่ทางกลับกัน
- **แยก `lmds-enterprise` เป็น private wheel** — ตามแผน WS-7
- **นับ node ที่เป็น observed-not-owned ไม่ซ้ำสองฝั่ง** (hub ซ้อน hub — ดู `RELEASE.md §7`)
